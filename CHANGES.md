# Калькулятор ходки: пять улучшений — 09.10.2026

- Объёмы ордеров: локальные страницы сохраняют ID, цену и количество. Общий подбор покупает по ценовым ступеням, ограничивает каждый увиденный объём и не использует один ордер несколько раз в разных рецептах. Для быстрой продажи учитываются ступени заказов на покупку. В списке закупки цена взвешенная, ступени — в подсказке. Обычные котировки и старые записи без ID не становятся доказательством количества. По умолчанию объёмы применяются там, где они известны; есть отдельный строгий режим без неподтверждённых новых покупок.
- «Рынок / сроки продажи»: продажи рынка в день, срок реализации выбранного количества при заданной личной доле, необязательное ограничение партии на 1–365 дней. Доля по умолчанию 10% — пользовательский сценарий, не измеренная доля и не гарантия продаж. Нет истории при включённом ограничении — результат нельзя продавать в модели.
- «Ходки: план / факт»: сохранённые планы переживают перезапуск. Сверка количества и сумм закупки, взятых запасов, выпуска, продаж и остатков, платы станции, прочих и всех комиссий. Можно добавить ресурс вне плана. Отклонение прибыли разбивается по составляющим. Пустые поля неизвестны, прогноз не заполняет факты. Завершённый учёт создаёт одну связанную сделку в журнале; правки обновляют её, а открытый учёт убирает её из завершённых результатов. XP и физические запасы сверка не изменяет.
- Банк: отдельные имена контейнеров, объединение прочитанных участков по абсолютным ячейкам. Автопозиция требует однозначного перекрытия минимум двух строк с разными ресурсами; иначе нужно указать первую строку. Повтор просмотра и одинаковые стаки не увеличивают запас. Завершение снимка требует непрерывного покрытия от первой строки и отсутствия сомнительных ячеек; достижение низа подтверждает пользователь. Сортировка или перестановка требуют нового снимка. Цена подтверждённой покупки восстанавливается после совпадения общего прочитанного количества даже на нескольких участках.
- «Сценарии»: несколько именованных наборов маршрута, персонажа, веса, бюджета, выбранных ресурсов и лимитов, фокуса, тарифов, режима объёмов и срока продажи. Цены и запасы не копируются в сценарий: при расчёте берутся текущие.
- Проверка: 194 Python-теста; проверки окон и подбора на временных базах, включая ценовые ступени, ограничения продаж, сохранение и восстановление сценария, сверку без дублей в журнале, перекрытие участков и чтение исходного скриншота банка. Реальные настройки, профиль и базы пользователя не изменялись.

# Запасы для ходки — 07.10.2026

- Добавлены запасы города переработки без веса перевозки и уже купленные партии города отправления с весом и сохранённой ценой. Бюджет ограничивает только новые покупки; допускается 0. Стоимость взятых запасов включается в прибыль и базу ROI. Общий целочисленный баланс выбирает количество из каждого источника.
- «Запасы / чтение банка»: выбор области полных клеток, локальное распознавание ресурсов, тира, чар и количества, автоматическое обновление после двух совпавших чтений при игре на переднем плане. Есть импорт скриншота, ручное добавление и исправление. Повторный снимок заменяет видимую область, одинаковые стаки не склеиваются; скрытые клетки не читаются, прокрутка не суммирует страницы.
- Для банка без фактической цены используются явно обозначенные оценки. Цена купленного фиксируется при чтении и не меняется вслед за рынком. Новый объём стака сбрасывает старую цену. Неизвестная стоимость не становится нулевой.
- Новые завершённые заказы на покупку можно добавлять по подтверждающим письмам локального клиента после включения наблюдения. Используется сумма покупки, город и точное имя персонажа, повторы и старые письма исключены. Быстрая покупка пока не подтверждается; получение письма не заменяет сверку наличия ресурсов. Снимок и письма не суммируются.
- «Партия выполнена — XP / запасы» атомарно списывает взятые запасы и пишет опыт. Отмена в журнале восстанавливает оба, с защитой от перезаписи новых данных. Рыночные обновления, профиль и запасы отслеживаются отдельно от сохранённого расчёта.
- Проверка: 173 Python-теста, отдельная проверка окон, фонового подбора, списания и отмены на временных базах; на приложенном скриншоте верно распознаны все 12 видимых ячеек ресурсов. Профиль и рыночные данные пользователя не изменялись.

# Личный билд и свободная слава — 06.10.2026

- «Билды / рынок» → «Мой билд — подобрать дешевле»: выбор оружия, левой руки, шлема, брони, обуви, сумки и плаща. Для каждого слота задаётся свой тир/чары цели; заменяется только сочетание тира, чар и допустимого качества того же предмета. Можно перенести состав выбранного билда сайта. Выбор сохраняется.
- Подбирается самая дешёвая известная покупка с IP не ниже цели. IP берётся из игровой таблицы с качеством и бонусами сохранённого боевого профиля, включая модификатор мастерства тира. Общая кнопка тира не меняет цели сумки и плаща. Двуручное оружие исключает левую руку. Недостающие/старые цены отмечены; абсолютный минимум без полного покрытия рынка не обещается. Есть обновление цен замен и копирование списка покупок.
- «Прогресс / журнал» → «Свободная слава»: уровень одной специализации, распределение ради IP выбранного предмета или среднего IP всей ветки. Используются возрастающие требования конкретных узлов, сохранённые уровни/XP, общие бонусы специализаций и коэффициенты расходования свободной славы по слотам. Общее мастерство можно включить отдельно.
- Целочисленное распределение выбирает итоговые уровни под общий запас очков; при равном приросте экономит очки. Подбор IP не тратит остаток на неполный уровень; режим одного предмета учитывает весь получаемый XP. Решатель работает в отдельном процессе, ограничен по времени и сообщает, если максимум не доказан. Диапазон 0–100; без LP, элитных уровней и сброса имеющихся уровней.
- Расчёты не меняют профиль. Выполненное распределение записывается отдельной кнопкой с проверкой изменения профиля и отменой в журнале. Числовые поля имеют видимые стрелки и не меняются колесом.
- Проверка: 160 Python-тестов, изолированные проверки обоих окон и прежнего трекера билдов, полный перебор небольшой задачи, все 238 боевых специализаций. Рыночные данные и профиль пользователя не изменялись.

# Старые и подтверждённые заказы — 05.10.2026

- Фильтр «Текущие (подтверждённые)» исключает непроверенные записи предыдущего снимка. Старые ID не объединяются с новыми по названию или близкой цене; непроверенные записи доступны отдельно.
- Вместо нуля при отсутствии подтверждённых строк показано «Текущие суммы неизвестны» с последними известными суммами непроверенных записей. При частичном снимке они показаны отдельно от подтверждённого итога, с учётом города и стороны.
- Полученная страница очищает устаревшее сообщение о неизвестном событии. Отменённый заказ сохраняет своё состояние после истечения срока.
- Проверка: регрессии снимка, фильтров, сумм и отмены; изолированное окно Qt. Реальные записи не изменялись.

# Обновления собственных заказов — 05.10.2026

- Расширенный локальный клиент версии 2 принимает подтверждённые операции создания/отмены/изменения и чтение писем рынка. Открытие формы и ошибка сервера не создают заказ. Канонические полные ответы обрабатываются сразу; неизвестные короткие форматы требуют сверки со страницей собственных заказов и сохраняются локально для диагностики.
- Отмена применяется по ID, письма — только при однозначном датированном совпадении. Повторные письма, другой персонаж, неоднозначные совпадения и старые страницы не списывают посторонние заказы. Терминальные состояния защищены от восстановления старым снимком.
- В окне добавлены сортировка двойным кликом по заголовку, фильтры города/стороны/состояния, оставшееся время в днях и часах с точной подсказкой. Себестоимость в данных сохранена. Завершённые строки скрыты из текущего списка. Обновления сохраняют ручные правки и объекты остальных строк.
- Проверка: 151 Python-тест, тесты Go клиента и Photon, изолированные проверки Qt сортировки/фильтров/обновлений и общего QoL. Пересобран исполняемый клиент; реальные рыночные данные и профиль не изменялись. Фактическое поведение коротких ответов сервера требует проверки в игре.

# Выбор цели калькулятора — 05.10.2026

- Добавлены сохраняемые режимы «Максимальная прибыль, серебро» и «Максимальный ROI, %». По умолчанию остаётся денежная прибыль; остаток бюджета допускается при заполненном весе.
- ROI оптимизируется как отношение прибыли к первоначальной закупке через последовательные целочисленные задачи, с общим лимитом времени. При равном ROI предпочтительна большая денежная прибыль. Режим доступен для цепочек и независимой переработки, с фокусом и без него.
- Проверка: 143 теста, изолированное окно Qt и копии рыночных данных/профиля. Полный перебор проверяет оба режима, начальные покупки, возвраты и фокус. Тайм-аут не выдаётся за доказанный ROI; денежная граница не используется как процентная.

# Общий подбор производственных цепочек — 05.10.2026

- Добавлена совместная целочисленная модель покупки, всех этапов переработки и продажи. Предыдущие тиры подключаются автоматически; промежуточный материал можно изготовить, купить или сочетать оба способа.
- Общие запасы распределяются между рецептами. Промежуточные результаты, используемые дальше, не продаются повторно; отрицательная отдельная рентабельность не исключает необходимый этап цепочки.
- Оптимизируется денежная прибыль: остатки явно показаны, но не прибавляются к выручке. Проверяются начальный вес и бюджет, каждый префикс выполнения, конечные остатки, фокус и денежный баланс независимой симуляцией.
- Фокус распределяется между этапами при стартовых уровнях. При смешанном выполнении с фокусом сначала проводится вариант с большим возвратом, затем без фокуса; XP и прогноз расхода соответствуют порядку исполнения.
- Добавлен дневной производственный бонус. Неизвестные покупки могут заменяться производством; пути без источника ингредиентов исключаются. Обновление цен охватывает промежуточные рецепты.
- Таблица разделяет производство, продажу и внутренний расход. Сравнение городов использует только реально продаваемые результаты. Максимум заявляется при доказанном решении модели; при тайм-ауте показана верхняя граница.
- Прежний независимый режим сохранён под галочкой. Проверка: 138 тестов, полный перебор маленьких цепочек, ручной вариант 304 тыс., изолированный Qt и копия реального рынка/профиля. Пустой план при тайм-ауте не объявляется доказательством отсутствия прибыли.

# Проверка модели и свежести цен — 05.10.2026

- Исправлено перекрытие свежей сохранённой котировки старым результатом главного окна: снимок объединяет стороны покупки и продажи отдельно по датам.
- Снятая галочка «Разрешить старые цены» теперь исключает рецепты со старыми входными/выходными ценами; старые цены других городов показываются как неизвестные.
- Добавлена «Проверка расчёта»: полный набор выбранных ресурсов, ингредиенты и цены, вес, возврат, станция, прибыль с/без фокуса за операцию, причины пропуска. Источники и даты доступны в подсказках; устаревшие цены отмечены явно.
- Подбор смешанных партий сверён с независимым полным перебором и пошаговой симуляцией запасов. Всего 127 тестов; проверен интерфейс и расчёт на копии рынка/профиля.

# Повторная переработка возвратов — 05.10.2026

- Калькулятор ходки по умолчанию повторно использует ожидаемые возвраты. Первоначальная закупка целых ресурсов и целое число операций подбираются совместно под вес, бюджет, фокус и ограничения выхода.
- Учтён запас ингредиентов до получения возвратов от последней операции. Выход оценивается по ожидаемому возврату, не обещается точный случайный результат игры.
- Плата станции, опыт и фокус включают все повторные операции. В остатках и прибыли учитываются только оставшиеся материалы; повторно использованные возвраты не считаются запасом второй раз.
- Прежний один проход доступен при снятой галочке; выбор сохраняется. Проверено на примере 5 000 руды по 16 / слиток по 22 при 40% возврата, сравнением с полным перебором небольших партий и проверкой начального запаса для рецептов с несколькими ингредиентами.

# Детализация прибыли ходки — 04.10.2026

- Плата станции и дополнительные расходы показаны отдельно; тариф станции задаётся за 100 питания, а прочие расходы — на каждый выход. Добавлено пояснение, чтобы не учитывать плату станции дважды.
- Итог показывает прибыль в процентах от первоначальной закупки; подсказка каждой строки раскрывает выручку, возвраты, закупку и расходы.
- Рыночные обновления не стирают готовый расчёт. Изменение относящихся к партии цен отмечается предложением пересчитать; посторонние предметы не вызывают предупреждение. Результат сохраняет свой снимок даже при поступлении цен во время подбора.
- При отсутствии прибыльной партии сравнение городов не показывает фиктивные нулевые суммы.
- Проверено 119 тестами, изолированным Qt-сценарием обновления цен и повторными расчётами на копии сохранённого рынка.

# Защита расчёта ходки от вылета — 04.10.2026

- Результаты, ошибки и завершение фонового решателя передаются явно через queued-соединения в Qt-слоты главного потока; обновление окна из потока расчёта запрещено.
- Ошибка показа результата записывается в журнал и отображается в окне; запоздалые результаты после закрытия игнорируются. Логируется начало и завершение подбора. Для pythonw добавлена запись стека нативного падения в albioncraft-crash.log.
- Проверены повторные расчёты, искусственный отказ решателя и скрытый нативный Windows-интерфейс на отдельных копиях сохранённых рыночных данных и профиля.

# Калькулятор ходки — 04.10.2026

- Отдельный целочисленный подбор партии переработки через SciPy / HiGHS: максимальная прибыль под полный первоначальный вес, бюджет закупки, доступный фокус и необязательные индивидуальные лимиты. Выбираются только отмеченные ресурсы, обычные рецепты без фракционных токенов; руда, волокно, шкуры, дерево, камень.

- Таблица имеет страницы по 100 строк без потери остальных результатов. Выбранная сортировка по чистой прибыли или ROI выполняется по всем вариантам до разбивки на страницы. Пустые расчёты ниже числовых. Есть отдельные сортировки с Focus. Заголовки соответствующих колонок также выбирают сортировку.
- «Что ищем»: крафт из ресурсов, зачарование готового предмета, межгородская перепродажа, перепокупка buy order → sell order. Столбец «Путь» убран; вариант рецепта остаётся в подробностях и при наведении.
- Для крафта, зачарования и перепокупки один город. «Все города» означает независимый расчёт в каждом городе, а не транспорт между ними. Только межгородская перепродажа использует разные города покупки и продажи.
- Зачарование: покупка предмета .0 выбранного качества и подтверждённых реагентов, продажа зачарованного результата. Нет RRR и Focus, не взимается станция крафта. Если есть дополнительные расходы зачарования, их нужно включить в прочие расходы. .4 не генерируется без подтверждённого рецепта.
- Перепокупка: ориентир buy_price_max для buy order, sell_price_min для sell order, комиссия размещения учитывается с обеих сторон. Налог продажи взимается с продажи. Формула: прибыль = sale × (1 − setup − tax) − buy × (1 + setup) − прочие расходы; капитал = buy × (1 + setup) + sale × setup + прочие расходы. Заказы в игре приложение не размещает. Котировки — ориентиры, объём и время исполнения неизвестны.
- Межгородская перепродажа: покупка готового предмета по sell_price_min, продажа по выбранной стороне рынка. Транспорт указывается в прочих расходах; Focus и рецепты ресурсов не нужны. Предметы с несколькими рецептами не дублируются.
- «RRR и комиссии» по умолчанию открывает общий профиль для всех предметов. Индивидуальный профиль рецепта может его переопределять по заполненным полям. Для общего профиля нужно подтвердить RRR и станцию по городам; комиссии и прочие расходы вводятся один раз. Общий профиль является пользовательским сценарием: фактическая станция и городской RRR могут отличаться по предмету.
- При отсутствии настроек программа показывает доступную маржу до RRR, станции и комиссий, явно подписанную «Маржа», и причину невозможности чистого расчёта. Маржа не называется чистой прибылью и не получает цвет надёжной прибыльности. Если нет цен компонентов, числовая маржа также не вычисляется. После сохранения общего профиля чистая прибыль сразу пересчитывается без нового API-запроса.

Неизвестные игровые расходы по-прежнему не подставляются нулями. В торговых режимах RRR и станция не требуются; комиссии и прочие расходы всё равно должны быть заданы. Последнее требует одного заполнения общего профиля, а не ввода для каждого предмета.

Проверено: 40 unit tests, четыре режима UI на живых ценах, сохранение общего профиля, пакетная обработка 1840 рецептов с тестовым API без ограничения 200. Зачарование дополнительно проверено на контрольных котировках с качеством 3. Тестовые коэффициенты не записывались в рабочие настройки.
